# 결과 생성 품질 분석과 개선 방향

## 문서 목적

현재 효용 검증용 LLM 결과가 왜 사용자의 실제 성향을 깊이 있게 설명하지 못하는지 분석하고,
Pakit이 지향하는 공유 가능한 `나 사용 설명서` 품질에 도달하기 위한 개선 방향을 정리한다.

현재 LLM 전체 생성 프로토타입은 목업 결과 방식으로 롤백됐다. 이 문서는 다음 결과 생성 구조를
새로 설계할 때 참고하기 위해 보존한다.

이 문서는 확정 구현 명세가 아니다. 관찰된 문제와 원인 가설, 권장 파이프라인, 추가 제품 결정을
구분한 분석 문서다. 실제 구현 전에는 아직 확정되지 않은 채점 규칙과 결과 문구 정책을 별도로
결정해야 한다.

## 목표 품질

PRD가 정의한 핵심 가치는 다음과 같다.

- 같은 유형에게 반복되는 일반론이 아니라 실제 응답으로 쓰인 설명서
- 사용자가 읽고 `어, 나 진짜 이런데`라고 느끼는 정확한 개인화
- 친구와 연인이 `이 사람을 이렇게 이해하면 되겠다`고 느끼는 관계 정보
- 결과 자체를 보여주고 싶게 만드는 장난감 콘셉트와 가벼운 재미

따라서 좋은 결과는 선택한 답변을 자연스럽게 다시 말하는 데 그치지 않아야 한다. 여러 응답에서
반복되는 행동 원리와 맥락에 따른 차이를 찾아, 참여자와 가까운 사람이 실제로 체감할 수 있는
설명으로 재구성해야 한다.

## 관찰된 품질 문제

대표 결과에서 다음 문제가 확인됐다.

| 생성 문구 | 문제 | 원인으로 추정되는 입력 |
|---|---|---|
| `충전 케이블을 챙겨준다` | 본인이 배터리 충전을 자주 잊는다는 답을 타인을 챙기는 성격으로 바꿈 | `low_battery` |
| `걷기 싫어하는 사람과 충돌한다` | 싫어하는 여행 상대를 참여자 본인의 성향이나 일반 주의사항으로 뒤집음 | 호환성 전용 `hates_walking` |
| `기상 직후 30분` | 데이터에 없는 구체적인 시간을 생성 | `after_waking` |
| `끊임없는 사회적 자극은 소진시킨다` | 이를 직접 뒷받침하는 응답 없이 소진 조건을 추론 | MBTI 또는 휴식 답변의 과잉 해석 |
| `거리 두기 허용형부착감성, 없음` | 의미가 깨진 태그 생성 | 모델 출력 품질 및 검증 부족 |
| `그의 행동이 곧 애정` | 지정한 호칭과 문체를 지키지 않음 | 지시 준수 실패 |
| `신메뉴·새가게 모험가` | 선택지 표현을 제목으로 재포장했을 뿐 새로운 통찰이 없음 | 답변 직접 복사 |

이 결과는 JSON 구조와 필드 개수를 만족하지만, 의미의 타당성은 보장하지 못한다. 구조화 출력은
형식 검증 수단이지 해석 품질 검증 수단이 아니다.

## 원인 분석

### 1. 입력 데이터가 제공하는 깊이에 한계가 있다

현재 22문항은 주로 짧은 상황 선택과 행동 선호를 수집한다. 다음과 같은 정보는 없다.

- 선택 과정에서 망설인 정도와 번복 기록
- 중요하게 여기는 가치의 우선순위
- 처음 선택했다가 포기한 항목
- 실제로 가진 강점과 현재 열망하는 모습의 차이
- 행동의 이유를 설명하는 자유 응답

따라서 문항으로 확인할 수 있는 것은 생활 습관, 관계 반응, 표현 방식, 거리감, 새로움에 대한
태도에 가깝다. 이 데이터만으로 성장 배경, 숨은 감정, 직업 성향이나 깊은 내적 욕구까지 단정하면
개인화가 아니라 근거 없는 서사가 된다.

깊이 있는 결과를 만들려면 두 선택지가 있다.

1. 현재 문항에서 확인 가능한 범위 안에서 정밀한 행동·관계 설명을 만든다.
2. 더 깊은 통찰이 제품 목표라면 이유, 우선순위, 망설임을 수집하는 문항이나 상호작용 데이터를
   추가한다.

### 2. 문항과 결과 영역의 연결이 일부 맞지 않는다

현재 결과 재료 매핑에는 의미상 충돌이 있다.

- `multiple_alarms`, `low_battery`는 타인이 해주면 좋은 행동보다 생활 습관 또는 자주 발생하는
  버그에 가깝다.
- `after_waking`, `nag`는 상대가 피해야 할 행동인 주의사항에 적합하다.
- `step1.q09`, `step1.q10`은 호환성 전용 답변이므로 개인 특징, 충전, 주의사항의 근거로
  사용하면 안 된다.
- 충전 활동은 `step1.q07`, `step1.q08`의 실제 회복 행동을 우선 사용해야 하며, MBTI 일반론으로
  새로운 소진 조건을 만들면 안 된다.

입력 분류가 어긋난 상태에서는 프롬프트를 정교하게 만들어도 모델이 빈칸을 억지로 채우게 된다.

### 3. 한 번의 호출이 너무 많은 책임을 가진다

현재 한 번의 모델 호출이 다음 작업을 동시에 수행한다.

- 네 성향 축 점수 계산
- MBTI 기본 경향 해석
- 22개 응답 통합
- 포장 상자와 개봉 도구 선택
- 형용사 생성
- 인물 소개 작성
- 핵심 특징 4개 작성
- 사용 방법 4개 작성
- 주의사항 4개 작성
- 충전 점수와 활동 작성
- 구조화 출력 스키마 준수

모델은 깊은 분석보다 눈에 띄는 선택지를 결과의 각 칸에 빠르게 배치하기 쉽다. 계산, 분류,
근거 검증, 카피 작성을 한 단계에 묶으면 어느 문장이 어떤 근거로 만들어졌는지도 사후 검증하기
어렵다.

### 4. 프롬프트가 길고 방어적으로 누적됐다

잘못된 결과가 나올 때마다 금지 규칙과 나쁜 예시를 추가하면서 핵심 작업보다 예외 처리의 비중이
커졌다. 긴 프롬프트 자체가 항상 나쁜 것은 아니지만, 같은 지시가 반복되고 생성 목표와 검증 규칙이
섞이면 작은 모델의 지시 준수율이 떨어질 수 있다.

프롬프트에는 다음만 명확하게 남기는 편이 낫다.

- 역할과 독자
- 입력 정보의 의미와 우선순위
- 단계별 작업 목표
- 출력 영역별 책임
- 근거 없는 추론 금지
- 좋은 완성 결과 예시

### 5. 모델은 품질에 영향을 주지만 단독 원인은 아니다

`gpt-5-mini`는 비용과 지연시간을 중시하는, 잘 정의된 작업에 적합한 모델이다. 현재 작업은 짧은
행동 단서에서 일관된 인물상을 구성하고 자연스러운 한국어 카피를 쓰는 복합 작업이라 모델 역량의
영향을 받는다.

상위 모델은 문장력과 지시 준수율을 개선할 가능성이 있지만, 잘못된 문항 매핑과 단일 호출 구조를
그대로 두면 더 그럴듯한 오해를 생성할 수 있다. 따라서 모델 교체 전에 입력과 파이프라인을 먼저
정리하고, 동일 입력에 대한 블라인드 평가로 모델 차이를 측정해야 한다.

현재 관찰을 설명하기 위한 잠정 추정치는 다음과 같다. 정량 실험 결과는 아니다.

> 품질 문제의 약 30%는 모델 및 생성 편차, 약 70%는 데이터·문항 매핑·생성 구조에서 비롯된
> 것으로 추정한다.

## 권장 생성 구조

분석과 카피 작성을 분리한다.

```text
MBTI + 22개 응답
        │
        ▼
결정적 계산 및 입력 분류
- 성향 축 점수
- A/B 조합
- 명사·형용사·상자·도구
- 개인 결과 재료와 호환성 재료 분리
        │
        ▼
1단계: 인물 프로필 분석
- 기본 기질
- 반복 행동 패턴
- 관계 거리와 소통 방식
- 애정 표현 방식
- 강점과 강점의 그림자
- 충전·소진 조건
- 문맥에 따른 의외성
- 근거 question_id
- 추론 금지 항목
        │
        ▼
근거 검증
- 모든 주장에 유효한 근거가 있는가
- 호환성 답변을 본인 성향으로 사용하지 않았는가
- 입력에 없는 숫자·상황을 만들지 않았는가
        │
        ▼
2단계: Pakit 카피 생성
- 원본 질문과 선택지는 전달하지 않음
- 검증된 인물 프로필만 사용
- 결과 페이지 영역별로 중복 없이 작성
        │
        ▼
출력 검증 및 결과 스냅샷 저장
```

### 결정적 계산으로 옮길 항목

다음 항목은 제품 규칙이 확정되면 LLM이 아니라 서버에서 계산해야 한다.

- 네 성향 축 점수
- MBTI에 따른 캐릭터 명사
- 축 조합에 따른 A/B 코드
- 포장 상자와 개봉 도구
- A×B 매트릭스에 따른 형용사
- 고정 통계가 아닌 실제 희귀도

이렇게 하면 모델은 사람을 이해하고 문장을 쓰는 일에 집중할 수 있고, 같은 응답에 대한 분류가
호출마다 바뀌지 않는다.

단, 현재 다음 규칙은 아직 제품 결정이 필요하다.

- 축별 세 문항의 가중치와 집계 방식
- 카톡 개수의 점수 정규화와 정확히 300일 때의 판정
- 50점 경계 처리
- PRD A×B 매트릭스의 형용사 후보를 최종 문구로 확정할지 여부

### 1단계 분석 결과 예시

1단계는 사용자에게 노출하지 않는 내부 데이터다. 각 주장에 근거를 연결한다.

```json
{
  "core_portrait": "관계의 애매함은 빠르게 정리하지만 친밀감의 속도와 거리는 직접 조절한다.",
  "patterns": [
    {
      "claim": "갈등을 미루기보다 먼저 확인하고 결론을 내린다.",
      "evidence_question_ids": ["step2.q02", "step2.q03"],
      "confidence": "high"
    }
  ],
  "tensions": [
    {
      "claim": "표현은 빠르지만 모든 일상을 공유하는 관계를 원하지는 않는다.",
      "evidence_question_ids": ["step2.q01", "step2.q02", "step2.q05"],
      "confidence": "high"
    }
  ],
  "care_style": {
    "claim": "말보다 필요한 행동을 먼저 하는 방식으로 마음을 표현한다.",
    "evidence_question_ids": ["step2.q08"],
    "confidence": "medium"
  },
  "unsupported_inferences": [
    "직업과 업무 방식",
    "성장 배경",
    "기상 후 필요한 정확한 휴식 시간",
    "사회적 자극 전반에 대한 소진 여부"
  ]
}
```

`confidence`가 낮거나 근거가 하나뿐인 주장은 핵심 특징으로 확대하지 않고, 제한된 맥락에서만
사용하거나 제외한다.

### 2단계 카피 생성 원칙

2단계에는 원본 선택지 문구 대신 검증된 프로필을 전달한다.

- 결과 이름: 확정된 형용사와 명사를 사용
- 인물 소개: 핵심 기질, 의외성, 관계에서 알아둘 점을 연결
- 핵심 특징: 사회적 역할, 판단 방식, 애정 표현, 개인 리듬을 서로 겹치지 않게 설명
- 사용 방법: 상대가 해주면 좋은 행동과 그 이유
- 주의사항: 강점이 지나칠 때의 그림자와 오해를 줄이는 방법
- 충전 방법: 근거가 확인된 회복 행동과 소진 조건만 사용
- 포장과 개봉 설명: 결정된 축 조합을 장난감 비유로 짧게 설명

최종 문구에는 다음을 노출하지 않는다.

- 문항 ID와 선택지
- `이 답변에서 드러난다` 같은 분석 근거
- MBTI 유형명에 의존한 일반론
- 내부 축 이름과 점수 계산 과정
- 입력에 없는 숫자, 시간, 경험

## 문항 재분류 제안

아래는 구현 전 검토가 필요한 제안이다.

| 문항 | 현재 또는 기존 역할 | 제안 역할 |
|---|---|---|
| `step1.q01`, `step1.q02` | 핵심 특징 | 사회적 역할과 강점 |
| `step1.q05`, `step1.q06` | 주의사항 | 취급 주의와 관계 트리거 |
| `step1.q07`, `step1.q08` | 충전 | 회복 행동과 에너지 리듬 |
| `step1.q09`, `step1.q10` | 호환성 | 개인 결과 생성에서 제외하고 호환성에서만 사용 |
| `step2.q01`~`step2.q12` | 축 점수와 결과 문구 | 축 계산 및 인물 프로필의 보조 근거 |

결과 생성에 사용되지 않던 `step1.q03`, `step1.q04`는 `2026-08-18.1` 문항 계약에서 삭제했다.
PRD의 결과 페이지에는 `자주 발생하는 버그`가 별도 항목으로 정의돼 있지만 현재 API 계약에는
독립 필드가 없다. 필요한 경우 새 문항과 결과 계약을 함께 확정해야 한다.

## 품질 검증 전략

프롬프트 수정만으로 완료 처리하지 않고 대표 입력에 대한 평가 세트를 운영한다.

### 골든 입력 세트

최소 다음 조합을 포함한다.

- 네 축이 모두 한쪽으로 강한 사람
- 네 축이 모두 반대쪽으로 강한 사람
- 표현은 직진이지만 거리를 두는 사람
- 표현은 조심스럽지만 친밀감을 원하는 사람
- 답변 사이에 의외성이나 긴장이 있는 사람
- 같은 MBTI이지만 22개 응답이 크게 다른 두 사람
- 0, 50, 100과 카톡 0, 300, 999 경계 입력

### 자동 검사

- 모든 내부 주장에 허용된 `question_id` 근거가 있는가
- 호환성 전용 문항이 개인 결과 근거에 포함되지 않았는가
- 입력에 없는 숫자나 시간 표현이 생성되지 않았는가
- 금지된 호칭과 내부 필드명이 노출되지 않았는가
- 형용사, 명사, 상자와 도구가 결정적 계산 결과와 일치하는가
- 동일한 통찰이 여러 결과 영역에서 반복되지 않는가
- 필수 필드와 항목 개수를 만족하는가

### 사람 평가

각 결과를 1~5점으로 블라인드 평가한다.

| 기준 | 질문 |
|---|---|
| 정확성 | 입력에 없는 사실을 만들거나 답변의 뜻을 뒤집지 않았는가? |
| 개인화 | 같은 MBTI 일반론이 아니라 이 응답 조합만의 특징이 보이는가? |
| 통찰 | 선택지를 반복하지 않고 여러 답변 사이의 관계를 설명하는가? |
| 유용성 | 친구나 연인이 관계에서 참고할 만한 내용인가? |
| 문체 | 자연스럽고 잘 읽히며 따뜻한가? |
| 재미 | 장난감 사용 설명서 콘셉트가 과하지 않게 살아 있는가? |
| 공유 의향 | 결과를 실제로 다른 사람에게 보여주고 싶은가? |

동일한 입력과 프롬프트로 여러 모델을 비교하고, 모델명을 숨긴 상태에서 평가한다. 평균 점수뿐
아니라 근거 없는 추론 발생률과 선택지 복사율을 함께 본다.

## Few-shot 예시 작성 원칙

완성 결과 3~5개는 모델이 아니라 사람이 먼저 작성하는 것을 권장한다. 예시는 단순한 문체 샘플이
아니라 다음 제품 기준을 보여줘야 한다.

- 같은 MBTI라도 답변에 따라 결과가 달라지는 방식
- 서로 반대처럼 보이는 특성을 맥락으로 설명하는 방식
- 강점과 그림자를 함께 말하는 온도
- 답변 문구를 노출하지 않고 근거를 녹이는 방식
- 사용자 본인의 습관과 상대방에게 요청할 행동을 구분하는 방식
- 재미있는 이름과 정확한 본문 사이의 균형

Few-shot 예시는 실제 사용자 데이터가 아닌 합성 응답으로 작성하며, 저장소에 개인정보를 넣지
않는다.

## 단계별 실행 제안

### 1단계: 입력과 결정 규칙 정리

- 문항별 결과 역할 재검토
- 호환성 답변을 개인 결과 입력에서 분리
- 축 점수와 경계 규칙 확정
- 명사, 형용사, 상자, 도구를 서버 계산으로 이동

### 2단계: 분석 프로필 도입

- 근거 ID와 신뢰도를 포함한 내부 분석 스키마 정의
- 근거 없는 주장과 역할 밖 문항 사용을 검증
- 원본 응답에서 분석 프로필을 만드는 1단계 생성 구현

### 3단계: 카피 생성 분리

- 검증된 프로필만 받는 짧은 카피 프롬프트 작성
- 사람이 작성한 완성 결과 3~5개를 few-shot으로 제공
- 결과 영역 사이의 중복 검사 추가

### 4단계: 모델 비교와 운영 결정

- 대표 입력 세트로 `gpt-5-mini`와 후보 모델 비교
- 품질, 지연시간, 호출 비용 측정
- 허용 가능한 품질 기준을 만족하는 가장 경제적인 모델 선택
- 운영에서는 모델 스냅샷과 프롬프트 버전을 기록

## 최종 판단

현재 품질 문제를 모델 교체만으로 해결하기는 어렵다. 우선순위는 다음과 같다.

1. 문항의 의미와 결과 영역 매핑을 바로잡는다.
2. 계산 가능한 분류를 서버의 결정적 규칙으로 옮긴다.
3. 분석과 카피 생성을 분리하고 근거를 검증한다.
4. 골든 평가 세트와 사람이 작성한 우수 예시를 만든다.
5. 마지막으로 모델별 품질과 비용을 비교한다.

Pakit이 제공해야 하는 것은 그럴듯한 성격 문장이 아니라, 제한된 데이터 안에서 과장 없이 이
사람의 반복되는 작동 원리를 찾아 친구에게 보여줄 수 있는 형태로 번역한 사용 설명서다.
