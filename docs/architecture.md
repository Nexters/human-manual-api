# 백엔드 설계 메모

## 현재 결정

- Python 3.12, FastAPI, Pydantic v2, `uv`를 기본 도구로 사용한다.
- 첫 단계는 모듈형 모놀리스로 시작한다. 서비스 경계가 검증되기 전에 마이크로서비스로 나누지 않는다.
- 결과 생성은 PRD에 따라 외부 AI API 없이 결정적(deterministic) 룰로 처리한다.
- HTTP 계약, 도메인 분류, 결과 조립을 분리해 콘텐츠와 저장소를 나중에 교체할 수 있게 한다.
- 축 점수는 화면의 좌우 위치가 아니라 필드 의미를 기준으로 정의한다. `attachment`는
  거리조절 0·밀착 100, `expression`은 탐색 0·직진 100, `routine`은 탐험 0·루틴 100,
  `egen`은 테토 0·에겐 100으로 사용한다.
- MBTI별 메인 캐릭터 16종은 최종 디자인 에셋과 동일한 고정 매핑을 사용한다.
- 테스트는 STEP 1의 8문항과 STEP 2의 12문항으로 구성된 고정 화면이며, 문구·레이아웃·에셋은
  프론트엔드가 관리한다. 서버는 버전별 문항/선택지 ID, 답변 검증, 채점 규칙을 관리한다.
- MBTI는 마지막 화면에서 E/I, S/N, T/F, J/P를 하나씩 선택하고 API에는 조합한 네 글자
  `mbti` 값으로 제출한다.
- 20개 답변은 문항 종류와 관계없이 `{question_id, value}` 형태로 제출한다. 서버가 문항
  계약을 기준으로 `value`의 문자열·정수 타입과 허용값을 검증한다.
- 결과 생성에 쓰이지 않던 `step1.q03`, `step1.q04`는 `2026-08-18.1` 문항 계약에서 삭제했다.
  개인 결과와 궁합 계산에 모두 쓰이지 않던 친구 선호 2문항도 `2026-08-19.2` 계약에서
  삭제했다. 뒤 문항의 안정적인 `question_id`는 유지하고 STEP 1의 표시 순서만 연속된 1~8로
  구성한다.
- `2026-08-19.3` 계약부터 `step2.q04`는 실제 프론트 화면과 동일하게
  `0·25·50·75·100`만 허용한다. 애착유형 점수는 직접적인 관계 거리 선택인 Q04 50%, 일상
  공유 Q05 30%, 카톡 개수 Q06 20%의 가중 평균을 가장 가까운 정수로 반올림한다.
- `2026-08-20.1` 계약부터 STEP 1 표시 순서는 피그마 화면과 동일하게 `q01`, `q05`, `q06`,
  `q07`, `q08`, `q12`, `q11`, `q02`로 구성한다. 문항 ID와 선택지 값, 채점 규칙은 유지한다.
- 결과 페이지의 희귀도 배지는 선택한 MBTI에 대응하는 고정 비율을 `상위 n%` 형태로 표시한다.
  비율은 2026-08-18에 확정한 16개 MBTI별 희귀도 표를 기준으로 하며, 생성 당시 문구를 결과
  스냅샷에 저장한다.
- 결과 페이지의 최종 결과명은 성향 축으로 정한 `형용사`와 MBTI로 정한 `명사`를 합쳐
  `형용사 + 명사`로 만든다.
- 결과 응답은 캐릭터 매핑용 `character_id`와 서버 정적 에셋의 절대 URL인 `image_url`을
  제공한다. 스냅샷에는 배포 환경을 옮길 수 있도록 상대 경로를 저장하고, HTTP 응답에서 현재
  백엔드 요청의 스킴과 호스트를 붙인다. 따라서 운영에서는 `https://api.pakit.kr/assets/...`,
  로컬에서는 `http://localhost:8000/assets/...` 형태로 반환한다.
- 결과 화면의 성향 축 점수와 그 점수로 결정되는 포장 상자·개봉 도구는
  `unboxing_kit` 하나로 묶어 반환한다.
- 포장 상자와 개봉 도구는 결과 계약에 정의된 의미 기반 영문 ID를 사용하며 내부 코드
  `A1..A4`, `B1..B4`와 별도 이미지 키는 API에 노출하지 않는다. 프론트엔드는 각 항목의
  `image_url`을 그대로 사용한다. 정적 에셋 폴더와 파일명도 공개 `type`과 동일한 영문 이름을
  사용한다.
- 핵심 특징은 항상 4개를 반환하며 `동원력`, `관계 속의 나`, `마음 정리법`, `타고난 무기`
  순서로 구성한다. 앞의 세 슬롯은 테스트에서 확인된 실제 답변을 근거로 하고, 마지막 슬롯은
  MBTI 16종 각각의 대표 특징을 사용한다. 마지막 슬롯은 MBTI를 일부 글자나 유형군으로 묶지
  않고 제출된 네 글자 전체를 기준으로 16개 결과 중 하나를 선택한다. 다른 결과 영역과의 경계와 세부 기획은
  `docs/key-feature-product-plan.md`를 따른다. 동원력 슬롯은 `step1.q11`을 중심으로 MBTI를
  보조 재료로 사용한다. 관계 속의 나는
  `step1.q01 × step1.q02`, 마음 정리법은 분류가 끝난 `표현방식 × 에겐테토` 두 축, 타고난
  무기는 MBTI 네 글자 전체만 사용한다. 마음 정리법에는 애착유형과 자극추구 축을 사용하지 않는다. 조합별
  네 슬롯의 결정적 매칭 로직은 구현됐다. 타고난 무기의 16종 카피는 현재 결과 페이지에서
  검수할 수 있으며 최종 문구 확정 전까지 콘텐츠 검수 대상으로 남긴다.
- `step1.q01`의 화면 질문은 `친구들이 나를 찾는 순간은 언제인가요?`로 표시하고, 네 선택지는
  결정·고민·놀이·정보가 필요한 순간을 짧은 문구로 보여준다. 기존 `question_id`와 선택지
  `value`는 유지한다.
- `step1.q02`의 화면 질문은 `친구들과 있을 때, 나와 가장 닮은 토끼는?`으로 표시한다. 네
  말풍선은 각각 정리·조율, 분위기 전환, 실행·추진, 관심·배려를 나타낸다. 백엔드는 역할 기반
  선택지 값과 말풍선만 관리하며 토끼 이름이나 에셋 매핑은 알지 않는다. 프론트엔드가 각 선택지에
  표시할 토끼 에셋을 결정한다. `step1.q01 × step1.q02`의 관계 결과는 4×4의 16개 고정 문구로
  생성한다. 선택지 값 변경에 따라 문항 계약 버전은 `2026-08-19.1`, 결과 콘텐츠와 궁합 파생
  프로필 버전도 `2026-08-19.1`로 올린다.
- `step1.q11`의 화면 질문은 `집에만 있으려던 주말, 나를 밖으로 나오게 한 건?`으로 표시하고,
  여섯 선택지는 각 동원 원인을 짧은 명사구로 보여준다. 기존 `question_id`와 선택지 `value`는
  유지하므로 제출 계약과 결과 매핑은 바뀌지 않는다.
- `step1.q12`의 화면 질문은 `기분이 안 좋을 때, 가장 반가운 친구의 연락은?`으로 표시하고,
  다섯 선택지는 공감·활동 전환·혼자 정리·문제 해결·유머의 도움 방식을 짧은 연락 문구로
  보여준다. 기존 `question_id`와 선택지 `value`는 유지한다.
- 핵심 특징 카드 바로 아래에는 `character_story`를 표시한다. 이 이야기는 MBTI별 메인 장난감
  16종에 하나씩 대응하는 고정 제목과 설명이며, 장난감의 움직임·구조·놀이 방식과 PRD의 대표
  성향을 연결해 왜 이 장난감이 도착했는지 설명한다. MBTI 코드와 내부 계산 과정은 노출하지 않는다.
- 사용 방법과 주의사항은 각각 4개, 충전 활동은 3개를 반환한다. 사용 방법은 힘들 때 원하는
  도움, 편안한 관계 거리, 갈등을 푸는 방식, MBTI별 호감 포인트 순서로 구성한다. 첫 슬롯은
  `step1.q12 × MBTI 가운데 두 축`, 두 번째는 애착유형 점수의 `0~24`, `25~49`, `50~74`,
  `75~100` 네 구간, 세 번째는 서운함을 드러내는
  `step2.q02 × 갈등 메시지를 보내기 전 숙고 속도인 step2.q03`, 네 번째는 제출한 MBTI
  네 글자 전체에 대응하는 16종 고정 문구로 결정한다. `step2.q08`은 에겐테토 축과 궁합
  프로필에서만 계속 사용한다.
- 주의사항은 대화에서 상처받는 지점, 사회적 에너지 경계, 가장 빠른 분노 버튼, 유형별 발작 버튼
  순서로 구성한다. 첫 두 슬롯은 각각 MBTI의 `T/F`, `E/I` 축만 사용하고, 세 번째 슬롯은
  `step1.q06`, 네 번째 슬롯은 제출한 MBTI 네 글자 전체에 대응하는 16종 고정 문구로 결정한다.
- 충전 방법은 `step1.q07`, `step1.q08`, `step1.q11`, `MBTI`를 조합한다. 61자 이하의
  메인 설명은 평소 회복 메커니즘을 보여주는 `q07` 첫 문장과 다시 기운이 올라오는 계기인
  `q11` 두 번째 문장으로 구성한다. 키워드 3개는 평소 회복인 `q07`, 일정이 틀어졌을 때의 환기인 `q08`,
  MBTI별 대표 충전 방식에서 하나씩 만들며 모두 사용자 관점의 행동으로 반환한다. `q11`은
  핵심 특징이나 사용 방법의 문구를 반복하지 않고 충전 맥락으로만 해석한다. 계산 의미가
  확정되지 않은 충전 점수는 API에서 제공하지 않는다. 기존 결과 스냅샷에 저장된 목업 점수는
  과거 데이터 복원을 위해 유지하되 응답 직렬화에서 제외한다.
- 표현방식·에겐테토·자극추구 축은 세 문항의 신호를 같은 가중치로 평균하고 가장 가까운 정수로
  반올림한다. 애착유형 축은 Q04·Q05·Q06을 각각 50%·30%·20%로 가중한다. 카톡 개수는
  300 미만을 밀착 100점, 300 초과를 거리조절 0점, 정확히 300을 중립
  50점으로 계산한다. 각 축의 최종 점수가 50점 이상이면 100점 쪽 극으로 분류한다.
- 성향 축으로 포장지 A와 개봉 도구 B를 고른 뒤 PRD 07의 A×B 매트릭스에서 형용사를
  결정한다. 명사는 MBTI별 캐릭터 매핑으로 결정한다.
- A×B 조합별 상단 소개 제목과 설명은 기존 결과 스냅샷 복원을 위해 내부 데이터에는 유지하지만
  API 응답에서는 제외한다. 포장과 개봉 도구의 설명은 각각 A 4개, B 4개 고정 카피를 사용한다.
  모바일 결과 페이지에서 한 카드가 지나치게 길어지지 않도록 포장 설명은 220자, 도구 설명은
  180자 이내로 제한한다. 현재 콘텐츠 버전은 `2026-08-20.1`이며 STEP 1 응답이나 MBTI 해석을
  이 영역에 섞지 않는다.
- 상단 태그 3개는 MBTI 전체 유형의 대표 키워드 1개와 네 성향 축 중 50점에서 가장 멀리
  떨어진 두 축의 극점 키워드로 생성한다. 편차가 같으면 애착유형, 표현방식, 자극추구,
  에겐테토 순으로 선택한다. 새 결과부터 `2026-08-20.1` 콘텐츠 버전을 사용하며 기존 결과는
  스냅샷에 저장된 태그를 유지한다.
- 제출 응답의 형용사·장난감 명사·캐릭터·이미지·성향 점수·포장 상자·개봉 도구는
  제출한 답변과 MBTI로 결정한다. 핵심 특징도 네 슬롯별 결정적 규칙으로 생성한다.
  장난감 이야기는 제출한 MBTI에 대응하는 16종 고정 카피 중 하나로 결정한다.
  사용 방법과 주의사항도 각각 네 슬롯의 결정적 규칙으로 생성한다. 충전 문장과 키워드는
  `step1.q07`, `step1.q08`, `step1.q11`, `MBTI` 규칙으로 생성한다. 희귀도는 제출한 MBTI에
  대응하는 확정 비율로 생성한다.
- 테스트 제출마다 무작위 URL-safe 8자리 `result_code`를 발급한다. DB 고유 제약과 충돌 시
  재발급으로 코드 중복을 방지하며, 결과는
  `assessment_results` 테이블에 생성 당시 JSON 스냅샷과 문항·콘텐츠 버전을 함께 저장하고,
  결과 조회 API는 이 스냅샷을 반환한다. 결과 화면과 공유 조회에 필요한 닉네임은 결과
  스냅샷에 포함하며, 원본 답변은 보존 정책이 확정되기 전까지 저장하지 않는다. 닉네임이 없던
  기존 스냅샷은 `participant: null`로 반환한다.
- MVP 친구 궁합은 두 개의 실제 `result_code`로 저장된 결과를 조회해 두 사람의 결과 요약,
  시너지, 네 가지 관계 상세 분석, 각자에게 전할 팁, 오래 지내는 방법을 반환한다. 오래 지내는
  방법은 가장 잘 맞는 영역을 관계의 강점으로 짚고 가장 낮은 영역을 함께 만들 습관으로
  연결해 사람별 팁과 같은 진단을 반복하지 않는다. 관계 상세
  분석은 거리감·갈등·위로와 애정·함께 움직이는 리듬을 모두 보여준다. 계산은 테스트 답변과 성향 축 70%,
  MBTI 30%로 구성한다. 테스트 기반 계산은 관계 거리 20%, 갈등 속도 20%, 위로·애정 방식
  15%, 함께 움직이는 방식 15%로 나눈다. MBTI는 네 글자가 같은 개수를 보조 점수와 설명에
  반영하며 MBTI만으로 좋고 나쁜 관계를 단정하지 않는다.
- 궁합 응답의 두 사람 요약과 각 사람에게 주는 팁에는 캐릭터 `character_id`와 절대
  `image_url`을 함께 반환한다. 프론트엔드는 상단 장난감과 팁 아이콘에 같은 URL을 사용한다.
- 궁합 계산에는 `step1.q01 × step1.q02`에서 파생한 관계 역할, `step1.q11`의 동원력 유형,
  `step1.q12`의 원하는 위로, `step2.q02`의 갈등 방식, `step2.q08`의 애정 표현 방식을 쓴다.
- 원본 답변을 저장하지 않는 원칙을 유지하기 위해 새 결과 스냅샷에는 궁합 계산에 필요한 축약
  프로필과 프로필 버전 `2026-08-19.1`만 함께 저장한다. 기존 결과에 이 프로필이 없으면 궁합
  API는 `409 COMPATIBILITY_PROFILE_UNAVAILABLE`을 반환한다. 계산과 카피의 세부 규칙은
  `docs/compatibility-rules.md`에서 관리한다.
- 개인 결과 화면에는 상세 궁합 진입 전 미리보기인 `compatible_friends` 카드 2개를 함께
  반환한다. 아직 상대방의 실제 테스트 결과가 없는 영역이므로 MBTI별 주 추천 유형 1개와 네
  글자가 모두 반대인 보완 유형 1개를 고른다. 첫 카드 설명은 사용자의 `NT/NF/ST/SF`에 따라,
  두 번째 카드 설명은 실제 `routine × attachment` 성향 사분면에 따라 결정한다. 두 카드는
  추천 장난감 명사, 캐릭터 ID, 이미지 경로, 관계 설명을 결과 스냅샷에 저장한다.

## 아직 확정하지 않은 것

- 형용사 16종의 최종 카피
- 충전 점수의 의미와 계산 규칙
- `step1.q05`의 새 결과 노출 위치
- 로그인 여부, 익명 세션 보존 기간, 공유 링크 만료 정책

이 항목은 제품 결정 없이 스키마나 DB에 고정하지 않는다.

문항과 선택지 식별자는 `docs/assessment-identifiers.v1.json`에서 관리하며, 프론트·서버
양쪽의 불변 계약으로 사용한다. 프론트 표시 순서도 같은 파일의 `step`·`order`를 기준으로
정렬한다.

결과 페이지 와이어프레임을 기준으로 한 응답 계약은 `docs/result-page-contract.md`에 기록하며,
테스트 제출 API에 적용한다. 호환성은 현재 범위에서 제외한다. 성향 축, 형용사, 명사와 언박싱
아이템, 핵심 특징, 장난감 이야기, 사용 방법, 주의사항, 충전 설명과 활동은 규칙으로 결정하고
충전 점수는 API에서 제공하지 않는다.

PRD의 "축당 2문항 × 4축" 기술과 현재 22개 고정 테스트 화면은 구성이 다르다.
현재 API 기획은 사용자가 전달한 최신 화면 구성을 따르며, 실제 채점 규칙 확정 전까지 이 차이를
해소해야 한다.

## 권장 구현 순서

1. 원본 답변과 닉네임의 보존 기간·삭제 정책 확정
2. PostgreSQL 정기 백업과 복구 훈련 구성
3. 결과 문구 조합기를 남은 섹션으로 확장하고 골든 테스트 추가
4. 궁합 공유 이벤트 계측 추가

## API 원칙

- 현재 공개 API는 별도 버전 구간 없이 `/api` 아래에 둔다. 프론트엔드가 사용하는 테스트
  API의 정식 경로는 `/api/tests`로 한다.
- 프론트엔드 연동 전 계약을 단순화하기 위해 기존 `/api/v1` 경로는 유지하지 않는다.
  추후 하위 호환이 필요한 변경이 생기면 그 시점에 버전 정책을 도입한다.
- 내부 MBTI/축 판정과 사용자에게 보여 줄 표현을 별도 필드로 유지한다.
- 이미 공유된 결과가 콘텐츠 수정으로 바뀌지 않도록, 저장 단계에서는 결과를 스냅샷으로 보관한다.
- 문항/카피 변경은 버전을 갖도록 설계한다.
- MVP 운영 환경에서는 FastAPI와 PostgreSQL을 한 백엔드 서버의 Docker Compose로 실행한다.
  PostgreSQL은 외부 포트를 공개하지 않고 named volume에 데이터를 저장한다. 별도 DB 서버와
  블록 스토리지는 운영 부하와 복구 요구가 확인된 뒤 도입한다.
- 런칭 전 읽기 전용 어드민은 `/admin`과 `/api/admin/*`에서 제공한다. 백엔드의 단일 관리자
  자격 증명이 모두 설정된 경우에만 HTTP Basic 인증으로 열고, 운영 HTTPS와 배포 앞단 접근
  제어를 전제로 한다. 어드민 응답은 캐시하지 않는다.
- 백엔드가 확실히 관측할 수 있는 공개 결과 조회 200 응답과 궁합 계산 200 응답만
  `backend_usage_events`에 저장한다. 닉네임, 원본 답변, IP, User-Agent는 이벤트에 저장하지
  않으며 저장 실패는 공개 API 응답을 막지 않는다. 배포 이전 호출은 소급하지 않고
  `PAKIT_USAGE_TRACKING_STARTED_AT` 이후 생성 결과만 궁합 경험 비율의 분모로 사용한다.
- 결과 조회 후 궁합 전환율은 `result_viewed`가 먼저 기록된 고유 `result_code` 중 이후 같은
  코드가 `mine`인 궁합 완료 기록이 생긴 비율이다. 로그인 사용자가 없으므로 사람 수가 아닌
  결과 코드 기준 지표로 해석한다. 프론트 클릭·페이지뷰·유입 분석은 GA의 책임으로 남긴다.
- 로컬 개발에서는 `compose.local.yaml`을 함께 적용해 PostgreSQL만 실행하고, DB 포트는
  `127.0.0.1:5432`에만 공개한다. FastAPI는 호스트에서 `uvicorn --reload`로 실행한다.
- Alembic 마이그레이션은 API 컨테이너 시작 전에 실행하며 실패하면 새 API 컨테이너를 시작하지
  않는다. 첫 마이그레이션은 `assessment_results` 테이블을 생성하고 downgrade로 되돌릴 수 있다.
