# 백엔드 설계 메모

## 현재 결정

- Python 3.12, FastAPI, Pydantic v2, `uv`를 기본 도구로 사용한다.
- 첫 단계는 모듈형 모놀리스로 시작한다. 서비스 경계가 검증되기 전에 마이크로서비스로 나누지 않는다.
- 결과 생성은 PRD에 따라 외부 AI API 없이 결정적(deterministic) 룰로 처리한다.
- HTTP 계약, 도메인 분류, 결과 조립을 분리해 콘텐츠와 저장소를 나중에 교체할 수 있게 한다.
- 축 점수는 화면의 좌우 위치가 아니라 필드 의미를 기준으로 정의한다. `attachment`는
  거리조절 0·밀착 100, `expression`은 탐색 0·직진 100, `routine`은 탐험 0·루틴 100,
  `egen`은 테토 0·에겐 100으로 사용한다.
- MBTI별 메인 캐릭터 16종은 최종 디자인 에셋과 동일한 고정 매핑을 사용한다.
- 테스트는 STEP 1의 12문항과 STEP 2의 12문항으로 구성된 고정 화면이며, 문구·레이아웃·에셋은
  프론트엔드가 관리한다. 서버는 버전별 문항/선택지 ID, 답변 검증, 채점 규칙을 관리한다.
- MBTI는 마지막 화면에서 E/I, S/N, T/F, J/P를 하나씩 선택하고 API에는 조합한 네 글자
  `mbti` 값으로 제출한다.
- 24개 답변은 문항 종류와 관계없이 `{question_id, value}` 형태로 제출한다. 서버가 문항
  계약을 기준으로 `value`의 문자열·정수 타입과 허용값을 검증한다.
- 결과 페이지의 희귀도 배지는 실제 사용자 통계가 아니라 현재 고정 문구 `상위 4%`를 사용한다.
- 결과 페이지의 최종 결과명은 성향 축으로 정한 `형용사`와 MBTI로 정한 `명사`를 합쳐
  `형용사 + 명사`로 만든다.
- 결과 응답은 캐릭터 매핑용 `character_id`와 서버 정적 에셋 경로인 `image_url`을 제공한다.
- 결과 화면의 성향 축 점수와 그 점수로 결정되는 포장 상자·개봉 도구는
  `unboxing_kit` 하나로 묶어 반환한다.
- 포장 상자와 개봉 도구는 결과 계약에 정의된 의미 기반 영문 ID를 사용하며 내부 코드
  `A1..A4`, `B1..B4`와 별도 이미지 키는 API에 노출하지 않는다. 프론트엔드는 `type`으로
  이미지를 매핑한다.
- 핵심 특징은 항상 4개를 반환하며 `동원력`, `관계 속의 나`, `마음 정리법`, `타고난 무기`
  순서로 구성한다. 앞의 세 슬롯은 테스트에서 확인된 실제 답변을 근거로 하고, 마지막 슬롯은
  MBTI 16종 각각의 대표 특징을 사용한다. 마지막 슬롯은 MBTI를 일부 글자나 유형군으로 묶지
  않고 제출된 네 글자 전체를 기준으로 16개 결과 중 하나를 선택한다. 다른 결과 영역과의 경계와 세부 기획은
  `docs/key-feature-product-plan.md`를 따른다. 동원력 슬롯은 `step1.q11`을 중심으로 MBTI를
  보조 재료로 사용한다. 관계 속의 나는
  `step1.q01 × step1.q02`, 마음 정리법은 분류가 끝난 `표현방식 × 에겐테토` 두 축, 타고난
  무기는 MBTI 네 글자 전체만 사용한다. 마음 정리법에는 애착유형과 자극추구 축을 사용하지 않는다. 조합별
  네 슬롯의 결정적 매칭 로직은 구현됐다. 타고난 무기의 16종 카피는 현재 결과 페이지에서
  검수할 수 있으며 최종 문구 확정 전까지 콘텐츠 검수 대상으로 남긴다.
- 핵심 특징 카드 바로 아래에는 `character_story`를 표시한다. 이 이야기는 MBTI별 메인 장난감
  16종에 하나씩 대응하는 고정 제목과 설명이며, 장난감의 움직임·구조·놀이 방식과 PRD의 대표
  성향을 연결해 왜 이 장난감이 도착했는지 설명한다. MBTI 코드와 내부 계산 과정은 노출하지 않는다.
- 사용 방법과 주의사항은 각각 4개, 충전 활동은 3개를 반환한다. 사용 방법은 힘들 때 원하는
  도움, 편안한 관계 거리, 갈등을 푸는 방식, 애정을 알아보는 법 순서로 구성한다. 첫 슬롯은
  `step1.q12 × MBTI 가운데 두 축`, 두 번째는 애착유형 점수, 세 번째는 `step2.q02`, 네 번째는
  `step2.q08`로 결정한다. 정확히 50점인 애착유형은 밀착 쪽 문구를 사용한다.
- 주의사항은 대화에서 상처받는 지점, 사회적 에너지 경계, 가장 빠른 분노 버튼, 건드리면 안 되는
  시간 순서로 구성한다. 첫 두 슬롯은 각각 MBTI의 `T/F`, `E/I` 축만 사용하고, 뒤의 두 슬롯은
  각각 `step1.q06`, `step1.q05`로 결정한다.
- 성향 축은 축별 세 문항의 신호를 같은 가중치로 평균하고 가장 가까운 정수로 반올림한다.
  카톡 개수는 300 미만을 밀착 100점, 300 초과를 거리조절 0점, 정확히 300을 중립
  50점으로 계산한다. 각 축의 최종 점수가 50점 이상이면 100점 쪽 극으로 분류한다.
- 성향 축으로 포장지 A와 개봉 도구 B를 고른 뒤 PRD 07의 A×B 매트릭스에서 형용사를
  결정한다. 명사는 MBTI별 캐릭터 매핑으로 결정한다. 충전 영역은 현재 목업값을 사용한다.
- 언박싱 키트의 상단 소개는 A×B 조합별 16개 고정 카피를 사용하고, 포장과 개봉 도구의
  설명은 각각 A 4개, B 4개 고정 카피를 사용한다. 현재 콘텐츠 버전은 `2026-08-15.8`이며
  STEP 1 응답이나 MBTI 해석을 이 영역에 섞지 않는다.
- 제출 응답의 형용사·장난감 명사·캐릭터·이미지·성향 점수·조합 소개·포장 상자·개봉 도구는
  제출한 답변과 MBTI로 결정한다. 핵심 특징도 네 슬롯별 결정적 규칙으로 생성한다.
  장난감 이야기는 제출한 MBTI에 대응하는 16종 고정 카피 중 하나로 결정한다.
  사용 방법과 주의사항도 각각 네 슬롯의 결정적 규칙으로 생성한다. 희귀도·상단 태그·충전 영역은
  해당 규칙이 확정될 때까지 기존 목업값을 유지한다.
- 테스트 제출마다 무작위 URL-safe 8자리 `result_code`를 발급한다. DB 고유 제약과 충돌 시
  재발급으로 코드 중복을 방지하며, 결과는
  `assessment_results` 테이블에 생성 당시 JSON 스냅샷과 문항·콘텐츠 버전을 함께 저장하고,
  결과 조회 API는 이 스냅샷을 반환한다. 결과 화면과 공유 조회에 필요한 닉네임은 결과
  스냅샷에 포함하며, 원본 답변은 보존 정책이 확정되기 전까지 저장하지 않는다. 닉네임이 없던
  기존 스냅샷은 `participant: null`로 반환한다.
- MVP 친구 궁합은 화면에 필요한 두 사람의 결과 요약, 시너지, 각자에게 전할 팁, 오래 지내는
  방법을 반환한다. `demo-result-code`와 `demo-friend-code` 조합만 지원하며 실제 궁합 점수와
  문구 규칙은 확정하지 않는다.

## 아직 확정하지 않은 것

- 형용사 16종의 최종 카피
- 충전 영역의 문구 조합 규칙
- 로그인 여부, 익명 세션 보존 기간, 공유 링크 만료 정책

이 항목은 제품 결정 없이 스키마나 DB에 고정하지 않는다.

문항과 선택지 식별자는 `docs/assessment-identifiers.v1.json`에서 관리하며, 프론트·서버
양쪽의 불변 계약으로 사용한다.

결과 페이지 와이어프레임을 기준으로 한 응답 계약은 `docs/result-page-contract.md`에 기록하며,
테스트 제출 API에 적용한다. 호환성은 현재 범위에서 제외한다. 성향 축, 형용사, 명사와 언박싱
아이템, 핵심 특징, 장난감 이야기, 사용 방법, 주의사항은 규칙으로 결정하고 충전 영역은
목업값으로 유지한다.

PRD의 "축당 2문항 × 4축" 기술과 현재 24개 고정 테스트 화면은 구성이 다르다.
현재 API 기획은 사용자가 전달한 최신 화면 구성을 따르며, 실제 채점 규칙 확정 전까지 이 차이를
해소해야 한다.

## 권장 구현 순서

1. 원본 답변과 닉네임의 보존 기간·삭제 정책 확정
2. PostgreSQL 정기 백업과 복구 훈련 구성
3. 결과 문구 조합기를 남은 섹션으로 확장하고 골든 테스트 추가
4. 호환성 규칙과 공유 이벤트 계측 추가

## API 원칙

- 현재 공개 API는 별도 버전 구간 없이 `/api` 아래에 둔다. 프론트엔드가 사용하는 테스트
  API의 정식 경로는 `/api/tests`로 한다.
- 프론트엔드 연동 전 계약을 단순화하기 위해 기존 `/api/v1` 경로는 유지하지 않는다.
  추후 하위 호환이 필요한 변경이 생기면 그 시점에 버전 정책을 도입한다.
- 내부 MBTI/축 판정과 사용자에게 보여 줄 표현을 별도 필드로 유지한다.
- 이미 공유된 결과가 콘텐츠 수정으로 바뀌지 않도록, 저장 단계에서는 결과를 스냅샷으로 보관한다.
- 문항/카피 변경은 버전을 갖도록 설계한다.
- MVP 운영 환경에서는 FastAPI와 PostgreSQL을 한 백엔드 서버의 Docker Compose로 실행한다.
  PostgreSQL은 외부 포트를 공개하지 않고 named volume에 데이터를 저장한다. 별도 DB 서버와
  블록 스토리지는 운영 부하와 복구 요구가 확인된 뒤 도입한다.
- Alembic 마이그레이션은 API 컨테이너 시작 전에 실행하며 실패하면 새 API 컨테이너를 시작하지
  않는다. 첫 마이그레이션은 `assessment_results` 테이블을 생성하고 downgrade로 되돌릴 수 있다.
