# 관계 설명서 입력 계약

상태: 런타임 프로필 변환 규칙 v1. 생성 결과 품질 검증 중이다.

## 목적

LLM에는 테스트의 질문과 답을 전달하지 않는다. 백엔드가 저장된 원본 응답 중 관계 분석에
필요한 항목과 관련 성향축을 결정적인 규칙으로 먼저 해석해, **각 사람에 대한 성향 설명**으로
바꾼 뒤 전달한다.

모델의 역할은 설문 해석이 아니라 이미 정리된 A와 B의 모습을 함께 읽어 관계를 분석하는
것이다. 이렇게 하면 문항 순서대로 답을 되풀이하는 현상을 줄이고, 같은 사람 안의 여러
특징을 연결하는 데 입력 토큰을 쓸 수 있다.

원본 응답은 DB에 계속 보존한다. 성향 설명을 생성한 규칙 버전과 원본 근거의 연결도 서버에서
보존하되, 기본 모델 입력에는 질문 원문·선택지·문항 ID를 넣지 않는다.

## 유저 프롬프트에 삽입할 구조

```markdown
## 사람 A 프로필

[해선]

- 성별: 여자
- MBTI: ENTP
- 연인 관계에서는 독립 0, 밀착 100 기준 13 정도로 각자의 시간과 영역을 넉넉히 두는
  관계를 편하게 느끼는 편이다.
- 마음에 드는 사람이 생기면 먼저 다가가고, 생각이나 감정도 비교적 즉시 표현한다.
- 서운한 일이 생기면 오래 미루기보다 그 자리에서 뜻을 확인하고 풀고 싶어 한다.
```

실제 입력에는 A와 B를 같은 형식으로 채운다. 각 줄은 질문과 답이 아니라 자연스러운 성향
설명이어야 한다. 내부에서는 구조화된 프로필을 유지할 수 있지만 모델에는 위와 같은 줄글
목록으로 렌더링한다.

성별은 현재 평가 제출과 원본 응답 스냅샷에 저장되지 않는다. 무료 궁합 화면의
`우리 관계 더 알아보기` 흐름에서 A와 B의 값을 입력받아 유료 관계 설명서 프로필에 넣는다.
기존 평가 결과는 수정하지 않으며, 이름과 MBTI로 성별을 추측하지 않는다.

## 프로필 생성 원칙

성향 설명은 LLM으로 미리 만들지 않고 질문지 버전에 묶인 문구 매핑과 조합 템플릿으로
생성한다. 같은 원본은 언제나 같은 설명으로 변환되어야 하며, 문장을 만든 근거는 서버 내부에서
추적할 수 있어야 한다.

선택지별 문구와 최종 줄글 조합은 분리한다.

```text
원본 선택값 → 선택지별 확정 문구 조각
관련 문구 조각 + 축 점수 + MBTI → 프로필 항목별 조합 템플릿
프로필 항목들 → romantic-user-template.md의 A/B 위치에 삽입
```

예를 들어 갈등 프로필은 서운함 처리 선택과 전송 전 숙고 선택을 각각 확정 문구로 바꾸고,
`conflict_and_processing` 조합 템플릿이 두 문장을 한 흐름으로 연결한다. 조합 단계에서도
새로운 심리 해석을 만들지 않는다.

- `relationship_distance`: `step2.q04` 하나만 사용한다. 저장값은 **독립 0, 밀착 100**
  방향이므로 변환 없이 설명한다. `attachment` 종합 점수와 다른 거리 관련 응답은 섞지 않는다.
- `approach`: 호감 상황에서 확인된 접근 방식을 설명한다. `expression` 종합 점수는 사용하지
  않는다.
- `conflict_and_processing`: 서운함 처리와 전송 전 숙고를 한 흐름으로 묶는다.
- `support_needs`: 받고 싶은 도움만 설명한다. 상대에게 주는 도움으로 바꾸지 않는다.
- `care_and_affection`: 애정을 표현할 때의 선호를 설명한다.
- `recovery`: 쉬는 날의 기본 회복 방식만 설명한다.
- `boundaries_and_sensitivities`: 관계에서 특히 불편한 행동을 구체적인 경계로 설명한다.
- `novelty_and_environment`: 메뉴, 가게, 금지 버튼 응답을 따로 설명하지 않고 세 답변의
  `routine` 종합 점수로 탐험형인지 루틴형인지만 판단한다. 타인의 반응을 받아들이는 방식은
  관련 문항으로 덧붙인다. 공간 취향은 사용하지 않는다.
점수의 진단 한계, 답변이 실제 사건은 아니라는 점, 받고 싶은 도움과 주는 도움을 구분하는
규칙은 개인 프로필마다 반복하지 않는다. 이런 해석 제한은 연인용 시스템 프롬프트에서
한 번만 전달한다.

서로 관련된 여러 응답은 하나의 문장으로 합친다. 서로 모순되어 보이는 응답은 하나를 버리지
말고 “이 상황에서는 이렇지만, 다른 상황에서는 저럴 수 있다”는 복합적인 설명으로 보존한다.
카톡 개수나 게임형 문항처럼 해석 범위가 좁은 값은 다른 정보와 같은 방향일 때만 보조적으로
반영하고, 단독 성향 문장을 만들지 않는다.

## 모델에 넣지 않을 것

- 테스트 질문 원문과 선택지
- `question_id: value` 형태의 원본 답변
- `derived_from`, 축 계산식, 가중치 등 내부 계산 정보
- 결과 캐릭터·형용사·개인 결과 카피와 기존 무료 궁합 문구
- MBTI 유형의 일반 설명을 미리 풀어 쓴 문장. MBTI 코드는 그대로 전달하고 관계 분석 단계에서
  다른 성향 정보와 결합한다.
- 닉네임에 포함된 ‘밀착’, ‘독립’ 같은 실험용 힌트
- 응답 시간·수정 횟수처럼 수집하지 않은 정보
- LLM이 한 차례 추측해 만든 개인 요약

## 생성 전 검증

- A와 B 모두 같은 프로필 항목을 갖는가?
- 관계 거리의 방향이 독립 0, 밀착 100으로 통일됐는가?
- 관계 분석에서 제외하기로 한 문항이 프로필에 억지로 포함되지 않았는가?
- 한 원본 응답을 서로 독립된 여러 사실처럼 중복 반영하지 않았는가?
- 약한 단서 하나가 강한 성격 단정으로 바뀌지 않았는가?
- 질문·답변·문항 코드와 기존 결과 카피가 모델 입력에서 제거됐는가?
- 프로필 버전으로 같은 입력을 재현할 수 있는가?
